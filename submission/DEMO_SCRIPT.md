# Six-portal demonstration

Use only the included fictional accounts. No PIN or password is needed. This walkthrough describes the connected application, not evidence of an authorized real-student pilot.

1. **HoD portal:** continue as Dr Sahana Krishnan. Home shows department totals and shortcuts. Open Courses & timetables. Publish CS401 with Dr Mira Sen if it is still a draft; choose a class time that does not clash. Existing published demo data can be used directly.
2. **Student portal:** continue as Ananya Rao. Open Course registration. If already submitted, show the saved selection; the hosted demo is intentionally left in that state. For a new submission after an authorized HoD reopening, select CS401, review the timetable and submit once. Refresh to show the locked selection. Explain that the HoD can reopen it with a recorded reason. Open Timetable and then LMS.
3. **LMS as faculty:** choose Dr Mira Sen. Open CS401 and inspect the existing lesson and graded assignment. To repeat the live submission demonstration, create a new assignment with a distinct title, due date and maximum marks. Attach an optional file smaller than 2 MB.
4. **LMS as student:** sign out, continue as Ananya Rao, open the lesson and submit an answer to the new ungraded assignment. The existing graded demonstration can be viewed without changing it. Show the submission time and saved work. These actions now contribute real LMS activity records within the synthetic demonstration.
5. **LMS as faculty, then student:** read the submission, publish marks and feedback, and sign in as Ananya again to show the same feedback. Explain that assignment scores are different from final course grades.
6. **Mentor portal:** open My timetable and a class. Publish attendance for today or an earlier date, assessment marks, or a final course result. Open My students and Ananya's record to show progress, LMS activity, fee status and support history.
7. **Mentor support:** open Support & follow-ups, Start review, then Start student review. Select Ananya and the focus. Expand Review thresholds to explain the synthetic policy. Choose Rules with validation for the hosted demonstration. Start the review. Missing or outdated evidence must be corrected before retrying. A language-model run can only be claimed when the actual recorded method says it used the model.
8. **Mentor decision:** open Suggestions, read the triggering evidence and suggested actions. Change the plan if needed, then confirm it with a reason. Add a follow-up and choose whether to share it. Explain that the agents prepare support and the mentor decides.
9. **Student and parent:** show the confirmed support plan. In Parent, check Attendance and Marks & results. Show published SGPA/CGPA and how many courses have results. In Fees & receipts, download the existing demo receipt. If an invoice is unpaid, record its demo payment first. No money moves.
10. **AI and HoD:** inspect a saved review's stages and recorded evidence. Use the HoD or Mentor account to demonstrate pause/resume or retry if unfinished work exists. The AI operator screen is for viewing status and evidence. Use HoD Students to inspect a profile and its correction history. Return to HoD Home to show the uncluttered department summary.

If no review is flagged, explain that the selected records did not cross the policy thresholds. Do not fabricate a concern to make a demonstration look busier. Use the documented synthetic fixtures or an approved real-case pilot with a recorded basis.
