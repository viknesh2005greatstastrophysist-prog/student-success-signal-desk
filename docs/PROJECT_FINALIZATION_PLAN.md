# Finalization plan and revised scope

12 October 2026. Planning method: installed Fable Thinking skill, followed by
eval-first Agentic Engineering. This record states decisions and acceptance
criteria, not private reasoning.

## Objective and verified foundations

Deliver a complete private six-portal academic and agentic support project using
only the supplied college exports as external data. Generate missing supporting
records under the owner's explicit instruction. Normal product copy is required;
data provenance stays in storage and technical documentation.

Verified inventory: twelve attendance/CIE XLS copies, six distinct workbooks,
321 students and 7,265 raw values. No ten college CSVs were located in Downloads.
The existing six-portal system, OIDC identity, PostgreSQL domain model and governed
four-source runtime can be reused. Raw report definitions remain unknown.

Usage constraint: account-wide usage must remain under 30%. Starting observation:
10% used. Account-wide readings are approximate and cannot establish exact task
cost. Prefer bounded generation and shared model results; no arbitrary new model.

## Initial plan

1. Preserve original reports, identity map, hashes, source cells and unknowns.
2. Generate missing accounts, relations, academic/LMS/career/fee operations with
   a deterministic seed, constraints and explicit machine-readable lineage.
3. Wire generated records and supplied raw evidence into the existing portal
   APIs and the governed agent pipeline; retain exact-artifact review authority.
4. Run the full system locally with real OIDC sessions and durable PostgreSQL.
5. Polish copy, motion, responsive states and every retained control.
6. Verify cross-portal mutations, permissions, repair/fallback, review/replay,
   idempotency and restart persistence. Review code and package the private project.

## Plan adjustment after evidence review

- Generated accounts are project accounts, not verified college identities.
  The earlier institution-only rollout remains separate and is not weakened.
- Do not infer percentages or marks from unexplained college values. Generate a
  distinct operational layer; surface the actual raw reports through scoped views.
  Agent evidence must retain source lineage and the report-definition unknowns.
- Use a local PostgreSQL runtime rather than uploading student names/reports to
  the existing cloud demo database. No public deployment, messages or real payments.
- Reuse the original APIs, transactions, OIDC/session protections and visual
  system. Add a dedicated project mode rather than replacing the working system.
- Whole-system acceptance uses representative accounts covering all roles plus
  the full imported cohort for generation/source integrity and agent processing.
- Generated policy approval and intervention decisions are project workflow
  actions. They are never recorded as actual faculty or institutional sign-off.

## Stop conditions and rollback

Refuse non-loopback private runtime URLs and cloud writes for this build. Stop a
pipeline on source hash mismatch, missing scope or invalid artifact; use explicit
fallback on model failure. Generated cohort initialization may create only its
dedicated project schemas and must preserve subsequent edits on rerun. Rollback
is stopping the local launcher and restoring the previous source revision;
source exports remain preserved outside generated tables. No real college
identity/permission claims can be manufactured by the generator.

## Required final report

Document implemented features, data boundary, architecture, agent stages,
permissions, execution results, run/setup commands, source/package fingerprints,
remaining limitations and which outcomes were actually verified. Report design
and runtime acceptance separately from production hosting or academic sign-off.
